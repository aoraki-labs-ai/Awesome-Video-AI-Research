0先分类:四种完全不同的工具

"benchmark 还是 VLM 评"之所以谈不清,是因为四类工具经常被混为一谈。它们评的对象不同、回答的问题不同、在迭代闭环里的位置也不同。

模型级 Benchmark BENCHMARK

评模型:固定 prompt 套件 + 固定评估器,输出一张模型能力表。回答"哪个模型强、强在哪个维度"。

VBench-2.0 · Video-Bench · VMBench · VideoPhy-2 · EvalCrafter

样本级 Judge / RM JUDGE·RM

评单条样本或样本对:给任意视频打分/排序。回答"这条比那条好吗"。能进训练闭环,也能当评测器。

VideoScore2 · UnifiedReward 系 · VideoReward(VideoAlign)· VisionReward

Meta:评裁判 META

评裁判本身:哪个 judge/RM 和人最一致、盲区在哪。回答"我该信哪把尺子、信到什么程度"。

MJ-Bench(图像) · VideoRewardBench · JudgeFit · Fooling LVLM Judges

Rubric 学习 RUBRIC

造尺子:从偏好对里自动学出加权自然语言准则,替代人手写 rubric / 黑箱 scalar RM。

AutoRubric-T2I · Auto-Rubric as Reward · EvalGen(流程原型)

页面内所有框架都带这四色标签;技术路线的差异比"用不用 VLM"重要得多。

1MJ-Bench:"专用小模型 vs VLM"这句话的完整证据链 META 图像域

先把我上次那句话补全并标出边界——它是图像域结论,外推到视频要打折。

评什么
22+ 个多模态"裁判",在同一批可验证偏好对上比准确率(错误事实/质量缺陷/安全隐患等构造出的成对样本)
裁判池
三类:专用打分模型(CLIP-score、PickScore、HPS-v2.1、ImageReward——百 M 到 B 级参数,输出标量)/ 开源 VLM(LLaVA 系、InternVL-chat)/ 闭源 VLM(GPT-4o、GPT-4V、Gemini Ultra、Claude 3 Opus)
四个视角
图文对齐(物体存在/属性/动作/位置/计数)· 安全(毒性/NSFW)· 画质(失真/模糊)· 偏见(职业×人口属性)
协议
成对二选一;数值分 [0-10] 与 Likert 两种反馈形态都测;指标含带/不带 tie 的准确率、NDS、GES;另用微调 SD-v1.5 做端到端人评回验

四条结论(逐条,不是一句话)

结论细节对我们的含义
① 专用打分模型赢在对齐与画质PickScore/HPS-v2.1/ImageReward 在 text-image alignment 和 image quality 两个视角上超过 VLM judges——这两个维度有可计算的判别信号,不需要世界知识客观可算维度(对齐、画质、闪烁、ID 一致性)优先用专用模型/检测器,便宜且更准
② 闭源 VLM 综合最好GPT-4o 平均分最高;VLM 的优势集中在需要推理的维度(安全、偏见)物理/常识/叙事类开放维度才是 VLM judge 的用武之地
③ 反馈形态影响精度VLM 用自然语言 Likert 档位比直接给 0-10 数值分更准更稳我们的 L1 judge 输出应设计为档位+理由,不是裸数值
④ 开源 VLM 在安全/偏见上不弱开源 VLM 在 safety 与 bias 检测上表现相对更强合规类闸门可以自部署,不必依赖闭源

外推边界:MJ-Bench 是图像域的 meta 评测(2024)。视频域的对应证据要看 §4 的 VideoRewardBench(视频理解 RM)与 §3 中各视频 RM 的对比实验;方向一致——判别信号强的维度小模型占优、推理维度大模型占优——但视频多了时序维度(运动/物理),那里目前既没有足够强的专用模型、VLM 也不可靠(见 VideoPhy-2 的 22% 与 JudgeFit 的 per-VLM 盲区),是三类工具都要组合使用的地带。

2模型级 Benchmark:四套技术框架 BENCHMARK

2.1 VBench-2.0 —— "通才 VLM + 专才检测器"混合体,18 维全拆

定位
从 VBench 1.0 的"表面保真"(像素质量/基础对齐)升级到"内在保真":物理、常识、人体、可控性、创意。每维约 70 条专用 prompt。
验证
每维做大规模人工偏好标注,报 Spearman 相关(逐维,论文 Fig.5);不是拍脑袋的自动指标。

它的真正价值在每个维度背后是什么打分器——这就是"能算的不让 VLM 判"在工业级 benchmark 里的实现:

2.2 Video-Bench —— 把"VLM 打分不稳"工程化解决的范本

定位
全维度用 MLLM(GPT-4o judge)评视频生成,9 个维度分两组:视频-条件对齐 5 维(物体/动作/颜色/场景/整体一致)+ 视频质量 4 维(成像/美学/时序一致/运动效果)。

两个机制值得直接抄:

Chain-of-Query(跨模态比对难 → 迭代问答) ① MLLM 先生成视频描述 → ② LLM 按维度出针对性问题 → ③ MLLM 带着问题重看视频作答 → ④ 用全部对话史 + 评分指引出分 Few-shot Scoring(绝对分没有锚 → 同批互为参照) 同一 prompt 的多个视频一起进上下文,互为隐式参照再打分 → 相关性提升 ~10.3%

与人的一致性(Spearman):0.50(全维平均),而人和人之间也只有 0.52——即 MLLM judge 已逼近人际一致性天花板;最好的维度是视频-文本一致(0.75)。这也是"judge 别追求超过人际一致性"的量化提醒。来源:arXiv 2504.04907

我们最关心的 motion quality 维度,VMBench 给了最完整的"专才组合"参考(1050 条经 GPT-4o+DeepSeek-R1+人工三重过滤的运动 prompt,覆盖流体/生物/机械/天气/群体/能量传递六类运动):

指标测什么技术栈
CAS 常识遵循是否符合物理/常识VideoMAEv2 时空 ViT,用 VideoReward 偏好模型预标的 1 万条视频训练,5 档 MOS

人对齐提升:五指标对人评的 Spearman 相关平均比既有指标高 +35.3%(逐指标 54.5%–77.1%),成对判别与人一致 70.6%。注意它的 CAS 本质是"用 RM 蒸馏出的专用小模型"——专才不一定要人工标,可以从 RM 蒸馏,这条路线对我们 L0 很有价值。来源:arXiv 2503.10076

2.4 VideoPhy-2 —— 物理:唯一敢报"很低的数"的 benchmark

构成
200 类真实动作、3940 条 prompt(动作中心,替代 1.0 的材料互动);人评 5 档 Likert,三轴:语义遵循 / 物理常识 / 显式物理规则命中(每条视频标注违反了哪条规则)
AutoEval
附带 VideoPhy-2-AutoEval 自动评估器(在其人评数据上训练),供快速回归
结果
hard 子集上最好模型 joint(语义+物理同时达标)仅 22%(v1 报告;后续版本收录更强模型后约 47.7%)——质量守恒/动量守恒类规则是重灾区

它的价值不在日常回归(维度窄),而在于:①物理 hard 集是真正拉得开模型差距的"最差集"(R2 的 hardmin 候选);②"显式规则标注"的做法是我们做物理维度 rubric 的模板。来源:arXiv 2503.06800

4.2 JudgeFit —— 每个 VLM 该有自己的评价维度

16 个 VLM(8 个家族)的实验:不同 VLM 对物理现象的内部表征不同,共用一套全局 rubric 等于假设所有裁判有同样的感知能力。方法:让目标 VLM 自己在样本上找物理错误并聚类成它的维度分类法 → 用人评校准逐维可靠性 → LLM 修复不可靠/冗余维度 → 迭代收敛。结果:比全局 rubric 平均好 ~32%,且暴露出"总排名看不出来的模型盲区"。对我们:L1 的 rubric 要按所选 judge 校准一轮,不能直接抄论文附录。来源:arXiv 2606.22918

4.3 Fooling the LVLM Judges —— 攻击面清单

多模态 judge 的已证实弱点:位置偏差(A/B 顺序影响判决)、评分不稳定(同输入多次不同分)、幻觉(评不存在的内容)、与人评实质分歧。工程对策:成对判定必须双向跑(交换 A/B 位置)取一致、temperature 固定、关键闸门多数投票。来源:arXiv 2505.15249

5Rubric 学习:把尺子本身变成可学习资产 RUBRIC

5.1 AutoRubric-T2I —— 算法逐步拆解

Phase 0 种子规则 从全量偏好数据选 256 个多样 pair(Composite Scoring:代理 reward × prompt 多样性平衡) → VLM 对每个 pair 做 CoT 分析,产出候选 rubric → 去重聚合成种子规则池 Phase 1..R 迭代精炼(每轮四步) (a) 用当前 rubric 集让 VLM 给训练 pair 打分(每条 rubric = 一个可打分特征) (b) ℓ1 正则逻辑回归 → 选 top-N 规则,稀疏化(弱规则权重归零) (c) hard-pair mining:找当前规则集判错的 pair (d) VLM 针对这些失败 pair 提出新规则 → 入池,下一轮 推理时:VLM judge 按「加权 rubric 集」逐条打分 → 加权合成 + 逐维反馈
指标数字说明
标注效率< 0.01%相对训练 scalar RM 的偏好数据量;几百-几千对即可起步
判准MMRB2 62.5%(Qwen3-VL-8B,免微调,SOTA)/ Gemini-3-Flash 71.4%8B 开源 judge + 学到的 rubric ≈ 微调 RM 水平
下游 RLSD-3.5-Medium 在 TIIF 65.3→71.6rubric 直接当 reward 用也有效
可审计性论文 Fig.2:HPSv3 scalar 优化会加"无关人物"骗分rubric 逐维分数能定位是哪条准则被违反——scalar RM 做不到

同族的 Auto-Rubric as Reward(副标题即"从隐式偏好到显式多模态生成准则")有开源实现,可作工程起点。来源:arXiv 2605.17602 / 2605.08354

5.2 三个必须一起吃下的约束

① 审美窄化(arXiv 2512.11883):通用审美对齐会把输出推向"平均好看",无法执行差异化风格指令 → rubric 按业务线/风格分组学,不学一套通用审美。② criteria drift(UIST 2024, arXiv 2404.12272):打分过程本身在定义标准,标准不可能先验写完 → rubric 版本化 + 记录每条的来源 case。③ 学出来的 rubric 也要过 meta 层:AutoRubric 的权重拟合数据 ≠ 校准数据,留出集纪律照旧。

7映射回三层栈:每个工具落在哪

层用什么(具体到组件)为什么是它
L0 夜跑闸门
每 checkpoint		VMBench 五件套(运动)+ VBench-2.0 专才维度(人体异常/ID/实例保持/几何)+ VideoReward 三维分 + VideoPhy-2 AutoEval(物理回归)+ 负样本反向校验全部可自部署、逐条便宜、有判别信号;MJ-Bench①/VBench-2.0 的实践都指向专才在这些维度更准
L1 成对评审
每实验		VideoScore2 + UnifiedReward(不同家族互查)+ 闭源 VLM 抽查;机制:chain-of-query、同批参照、Likert 档位+理由、双向 A/B、关键判定多数投票;rubric 按 JudgeFit 思路对所选 judge 校准开放维度需要推理(MJ-Bench②);形态设计全部有出处(Video-Bench/MJ-Bench③/Fooling)
L2 人评锚
每周/里程碑		200-prompt 分难度集 GSB;产出三用:决策数字 / L0-L1 的 TPR-TNR 校准 / 偏好对入库 → AutoRubric 学 rubric(按业务线分组)人际一致性 ~0.52 是所有自动 judge 的天花板参照;偏好对是唯一越攒越值钱的资产

一句话版本:L0 用"专才检测器 + RM 分数"守回归,L1 用"两个家族的生成式 judge + 校准 rubric"做成对裁决,L2 用人评校准一切并顺手生产偏好对喂 rubric 学习——四类工具各归其位,任何一层单独拿出来都不可信,合在一起才是尺子。
